# Claude Planner

## Overview
Designs high-precision, token-optimized implementation blueprints for Claude Code. Antigravity acts as the high-context Architect, absorbing codebase and specification analysis so Claude Code acts as a focused, surgical Executor.

## When to Use
- Preparing any multi-step task, feature, or refactor to be run in Claude Code.
- Designing 3D modeling pipelines or MCP-driven tasks (e.g. Blender MCP).
- When token conservation in Claude is critical.

Do NOT use for:
- Simple single-line edits that don't need a formal plan.
- Tasks executed entirely inside Antigravity without Claude Code handoff.

## Core Architectural Principles

1. **Absorb Context Overhead:** Claude burns tokens when exploring directories or reading files. Antigravity must pinpoint exact file paths, function signatures, and spatial constraints.
2. **Domain-Aware Abstraction:**
   - **Software / Code:** Highly prescriptive. Specify exact files, target functions, atomic steps, and test commands.
   - **3D Modeling / Blender MCP:** Spatial blueprint. Specify bounding boxes, metric scales, modifier setups, and quality checks. Allow Claude's spatial intelligence to generate and refine the actual geometry.
3. **Phased Execution with Checkpoints:** Divide work into 2–4 atomic phases. Every phase MUST conclude with a verification step and an explicit human checkpoint.
4. **Resilient Persistence:** Every task is a checkbox (`- [ ]`) in a markdown file stored in `docs/plans/YYYY-MM-DD-<topic>.md`.

## Plan Template Standard

Every plan generated by this skill must follow this structure and be saved to:  
`docs/plans/YYYY-MM-DD-<topic>.md`

```markdown
# [Plan] <Topic / Feature / 3D Model Name>

- **Target Agent:** Claude Code (with \`antigravity-executor\` skill)
- **Mode:** Phased with Review Checkpoints
- **Domain:** [Software | 3D Modeling / MCP]
- **Verification Command / Check:** [e.g. npm test -- path/to/test.ts | Blender scene inspection]

---

## Phase 1: <Descriptive Phase Name>
<!-- Goal: Self-contained milestone -->

- [ ] Task 1.1: <Exact action>
  - **Target:** <File path or Blender collection/object>
  - **Details / Constraints:** <What to modify or spatial bounding box / scale>
- [ ] Task 1.2: <Next atomic action>
- [ ] Verification 1.3: Run verification command or inspect result.
  - **Command / Check:** \`<command>\`
  - **Expected Outcome:** \`<exact success output / visual criteria>\`

> **[CHECKPOINT: User Review]**  
> Stop here. Inform user that Phase 1 is complete and verified. Wait for user confirmation before proceeding to Phase 2. Recommend running \`/clear\` to reset context before the next phase.

---

## Phase 2: <Descriptive Phase Name>
...
```

## Domain Guidelines

### 1. Software Engineering
- Always specify target file paths: `src/services/auth.ts`, not "the auth service".
- Provide the exact test command so Claude doesn't run the whole test suite:
  - Good: `pnpm vitest run tests/unit/auth.test.ts`
  - Bad: `run tests`
- Isolate steps so each task touches at most 1–3 related files.

### 2. 3D Modeling with Blender MCP
- Define metric dimensions and bounding boxes: e.g. `Base diameter: 0.60m, Height: 0.45m`.
- Provide collection hierarchies and naming conventions: e.g. Collection `Silla_Oficina`, Object `Piston_Hydraulic`.
- List recommended modifiers (Subsurf, Bevel, Solidify) and apply-transform rules (`Ctrl+A` scale/rotation apply).
- Do NOT micromanage every single vertex unless required; allow Claude to write the `bpy` geometry code and handle topology.

## Error Handling & Feedback Protocol

Include this notice at the bottom of every plan:
If a task fails after 1 quick self-correction attempt, Claude must pause, mark the task as blocked in the markdown plan, and generate a diagnostic block for Antigravity:

```markdown
### [ANTIGRAVITY DIAGNOSTIC REPORT]
- **Phase / Task Failed:** <Task ID>
- **Command / Action:** <Executed action>
- **Error Output:** <Exact error message / stack trace>
- **Suspected Cause:** <Brief 1-sentence note>
```
The user can paste this block into Antigravity to adjust the blueprint without wasting Claude tokens.
